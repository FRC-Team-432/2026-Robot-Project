# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

FRC Team 432 "The Final Countdown" 2026 robot codebase, built on [Hemlock's Gray Matter Template](https://github.com/Hemlock5712/2026-Template). Uses WPILib Command-based programming with CTRE Phoenix 6 motor controllers.

## Build Commands

```bash
./gradlew build              # Compile and build
./gradlew deploy             # Build and deploy to RoboRIO
./gradlew simulateJava       # Run desktop simulation with GUI
./gradlew test               # Run unit tests (JUnit 5)
./gradlew clean build        # Clean rebuild
```

## Architecture

### Command-Based Structure
- All robot actions are `Command` objects managed by the Command Scheduler
- Subsystems own hardware; only one command can use a subsystem at a time
- Commands compose via sequential, parallel, and conditional patterns

### Subsystem Organization
```
RobotContainer (setup & button bindings)
├── CommandSwerveDrivetrain (swerve drive, 4 modules)
├── Superstructure (coordinates arm + flywheel)
│   ├── Arm (position-controlled via Motion Magic)
│   └── Flywheel (velocity-controlled)
├── Intake (velocity-controlled roller)
└── LimelightSubsystem (AprilTag vision)
```

### Hardware Abstraction
Each subsystem has real and simulated implementations:
```java
public final Arm arm = RobotBase.isSimulation() ? new ArmSIM() : new Arm();
```

### Constants Pattern
Configuration lives in `constants/` classes (e.g., `ArmConstants`, `FlywheelConstants`). Motor CAN IDs, PID gains, setpoints, and tolerances are centralized here.

### Key CAN IDs
| ID | Device |
|----|--------|
| 1-8 | Swerve drive motors |
| 9-12 | Swerve CANcoders |
| 13 | Pigeon 2 gyro |
| 21 | Flywheel motor |
| 22 | Intake motor |
| 31 | Arm motor |
| 32 | Arm CANcoder |

All devices on CANivore bus (`"CANivore"`).

### Generated Code
`generated/TunerConstants.java` is auto-generated by CTRE Tuner X for swerve configuration. Regenerate via Tuner X if swerve tuning changes—do not edit manually.

## Code Patterns

### Command Creation
Use `startEnd()` for commands that run continuously and need guaranteed cleanup:
```java
public Command intakeCommand() {
  return startEnd(
    () -> setVelocity(INTAKE_SPEED_RPS),
    () -> stop())
    .withName("Intake");
}
```

### Telemetry
- `@Logged` annotation (Epilogue) for automatic field logging
- `HootAutoReplay` records motor data for playback debugging
- Log file path: `./logs/example.hoot`

## Tuning Status

**Arm PID gains are all 0.0 and require tuning** (see `ArmConstants.java`):
- kG, kS, kP, kD need characterization
- Motion Magic velocity/acceleration need configuration

Use Phoenix Tuner for PID characterization on real hardware.

## Autonomous

Autonomous routines in `autonomous/AutoRoutines.java`:
- `mobilityAuto()` - Drive to midfield
- `sequentialScoringAuto()` - Score, intake, score
- `parallelPreparationAuto()` - Prepare while driving
- `demonstrationAuto()` - Cycle all mechanism states

Path following uses `LinearPathRequest` with velocity-based control.
